# berichmyfriend.com 部署说明

> 当前状态：仅完成并验收 Mac 本地版。尚未执行 Vercel 发布、域名绑定或 DNS 修改。用户确认本地版本前，不进行以下线上步骤。

网站按“本地优先”方式工作：账号、密码摘要、任务、身体签到、建议和“问春风”报告只写入访问者当前浏览器的 `localStorage`。服务器不保存用户账户或这些个人记录。

Vercel 版本只分发静态 HTML、CSS 与 JavaScript。Mac 本机的 Apple Calendar 与本地 AI 桥不会自动出现在公网；上线后相关按钮必须显示“本机桥不可用”，直到另行设计并获批 Shortcut/服务端方案。

## 发布到 Vercel

在仓库根目录运行：

```bash
vercel login
vercel --prod
```

项目已通过 `vercel.json` 配置构建命令和 `web/dist` 发布目录。

## 绑定域名

1. 在 Vercel 项目中打开 **Settings → Domains**。
2. 添加 `berichmyfriend.com` 和 `www.berichmyfriend.com`。
3. 在域名注册商的 DNS 控制台按 Vercel 页面给出的值添加记录。通常根域名使用 `A` 记录，`www` 使用 `CNAME`；应以 Vercel 当时显示的值为准。
4. 等待 Vercel 显示域名验证通过和 HTTPS 证书生效。

## 数据迁移与备份

- 原本的 `study_state.json` 不会自动发布，也不会出现在网站源码中。
- 登录网站后，在“我的”中导入由本网站导出的账户 JSON 备份。
- 使用“备份全部数据”定期下载 JSON。清除浏览器数据、使用无痕模式或更换设备时，本地数据不会自动跟随。
- 导入会清除原设备的日历选择、事件 ID、同步状态与 AI 同意；新设备必须重新选择和确认。

## 隐私边界

这种账号是设备内账号，不是云账号：同一个用户名在另一台设备上需要重新创建，密码无法通过服务器找回。浏览器数据是明文存储，不应被描述为加密保险箱。若以后需要跨设备同步，必须增加后端数据库、真正的身份认证、数据加密与更新后的隐私政策。

AI 供应商配置只存在于 Mac 本机的 `~/Library/Application Support/Berich/config.env`，不会打包进 `web/dist`，也不得复制到 Vercel 环境。公网 AI 与日历能力需要单独的安全、隐私和部署计划。

## 公网环境数据上线前置检查

当前 Open-Meteo 适配器只用于本地非商业验收。把环境能力带到 `berichmyfriend.com` 前必须重新核实并记录：

1. 当时有效的商业许可、免费/付费额度、并发与速率限制；若当前端点不适用，则购买合规方案或替换供应商。
2. 页面和隐私政策中的供应商归属、数据时间、条款链接与 `stale / missing` 状态是否按供应商要求显示。
3. 由服务端代理固定允许主机，设置短超时、响应大小、缓存 TTL、限流和通用错误；浏览器不得携带八字、账户、问题或个人历史直连天气供应商。
4. 公网代理不得记录完整请求体、城市以外的个人内容、AI 原始响应或供应商密钥；日志和监控只保留必要的安全状态码与聚合指标。
5. 跨设备账户、用途授权版本、撤回、数据删除和加密方案已经设计并更新隐私政策，不能沿用“浏览器本地账户”假装云端认证。
6. iPhone/Mac Apple 日历仍需使用每位用户自己的快捷指令或后续获批方案；不得要求 iCloud 账号专用密码，也不得让公网服务器读取全部日历。

完成以上检查之前，公网静态版应明确显示本机桥与可信问春风外部环境能力不可用，不能悄悄回退为无来源的“实时天气”文案。
